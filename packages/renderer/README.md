# Deterministic scene rendering

`renderSceneHtml` is a synchronous, deterministic Node API. X, Jike, Threads
and Xiaohongshu use the editor's real `SceneView`, compiled to static React
markup. MCP uses the same pure document shell and CSS. The remaining legacy
skins, including offline Telegram, retain their existing HTML implementation.
All paths keep the fictional-content disclosure enabled by default.

The social adapter normalizes legacy optional scene fields and indexed assets,
filters all image sources to raster data URIs, then applies canonical scene
validation. Custom layouts also use SceneView. Remote images are omitted;
invalid layout, appearance, reference edits and asset indices are rejected.
Payment payloads are neutralized by the shared policy. No runtime filesystem,
network access or dynamic compilation is used; React's server renderer and the
existing icon package are runtime dependencies.

After changing SceneView or its dependencies/styles, run `npm run build:mcp`
and commit `generated/studio.mjs`. `npm run check:renderer` recompiles in memory
and compares every generated byte without overwriting the committed artifact.
The source digest includes bundled sources, CSS, compiler script and lockfile;
the CI test hook checks freshness before building. Generated output contains no
machine paths or local setup metadata.

`tools/eval/src/render.mjs` and the MCP capture service reject standard PNGs
when the frame or its message scroll region would clip content. Long PNGs
expand the same markup within their respective pixel limits. A configured
HTML document alone is not proof of a successful PNG capture.
