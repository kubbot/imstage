# 人物库、默认身份与设备截图

2026-09-21 实现：工作台右上角「人物与头像」、左侧默认人物入口；点选消息后直接展开元素编辑。人物可上传头像、通过现有 Agent 生图、编辑/保存/复用/移除。头像生成使用隔离的临时场景，只有点击保存才进入人物库。

## 身份生命周期

- 人物库按登录账户存储在服务端 SQLite，GET/PUT `/api/contact-library`；不依赖浏览器缓存。头像仅存储可解码的本地 PNG/JPEG/WebP 数据，不接受 URL 或伪装 SVG。
- 默认人物只补充空白新场景中尚未配置的「我」。已经打开的作品、手动选择的人物、已上传头像不被覆盖。
- 成功完成的生成会自动保存人物快照，可以关闭。失败、中断、单独的头像生成不会自动入库。后端同一包装层也适用于项目批量生成。
- 名字、头像、备注完全相同才去重；同名不同头像保留为不同人物。不通过姓名猜测现实身份。
- 应用联系人会复制姓名和头像到指定参与者，保留消息发送者 ID。修改或删除人物库记录不会联动修改已保存的作品。
- 重建场景保留选定设备；参与者 ID 改变时，仅对姓名及发送方匹配且唯一的人物复用头像。新场景默认「我」由确定性逻辑绑定，不依赖模型记住图片数据。
- 数据库用 revision 防止覆盖其他标签页更新。自动保存追加前重读；冲突或容量超限会明确提示，画面仍保留。单张头像 2 MiB 编码串、4 百万像素，库内最多100人/8 MiB图片字节。

## 设备与呈现

详见 `device-profiles.md`。新空白场景默认 iPhone 17 Pro；旧草稿/作品保留原尺寸。设备控件同时修改 surface 与 profile，普通 PNG 按 profile 的逻辑尺寸×DPR输出。预览缩放仅用于适应窗口，不改变消息排版。长截图保持同一宽度，随内容增高。参考截图编辑继续按源图尺寸输出，设备控件禁用。

编码模板负责状态栏、输入栏、头像尺寸与气泡排版。照片由图片 API 返回，不能用字母头像或占位方块通过真实性验收。macOS 是独立聊天窗口预设，不是整个显示器或完整微信主窗口。

## 新评测用例

`tools/eval/fixtures/device-fidelity.json` 中 D01—D06 覆盖 iPhone微信、Pixel微信、macOS微信、跨次人物复用、长截图、头像局部重绘。每个用例包含难度、问题、预期答案、硬断言；在 `/fidelity.html` 查看，截图数据集页面有入口。

浏览器测试 `tests/ui/contacts-devices.spec.ts` 使用合成 API 响应验证生命周期与真正的 PNG 下载尺寸；它不能证明模型自然度或生图质量。真实服务链路证据保留在忽略的 `.local/verification/contact-devices/`。新增用例的视觉金标保持待人工标注，没有自动把本轮输出当金标。

原有 C01—C11 的金标与阈值不变；本轮测试通过不能替代此前 6/11 的截图编辑验收结果。

## 本轮实测记录

- 核心自动测试：288 项通过；浏览器套件：53 项通过；Eval 工具：193 项通过。它们分别覆盖服务端持久化/隔离、交互/PNG 下载和评测工具，并不等同于真实感评分。
- 真实登录账户通过 DeepSeek 和已配置图片服务生成摄影头像，保存默认人物，生成两条对话并保存对方头像；三种尺寸 PNG 已实际下载。私有证据：`contact-panel.png`、设备 PNG、`export-metadata.json`。首轮浏览器流轨迹读取未成功，记录中明确标记，不据此宣称工具调用次数。
- 用户选择 iPhone 17 Pro 后，默认配置和 D01/D04/D05/D06 改为 402×874 @3x（1206×2622）；iPhone 15 Pro 的旧 profile 仍然有效。后续复用已生成头像验证不应再次生图。
- 独立复查修正了项目批量空白场景的默认身份入口；人物库读取失败不再阻断核心生成；头像解码仅处理当前账户未验证过的图片，仍对整库检查体积。
- 默认人物作为新场景的固定起始身份；若要更换名字或头像，可在人物库显式选择，或生成后选中对应人物进行局部编辑。局部头像生成先暂存，不静默覆盖默认记录。
