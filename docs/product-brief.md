# IMStage — 产品说明

状态：早期开发。本文整理用户提供的方向；未实现的能力均为规划。

## 已授权的 Eval 阶段

用户要求先建立多平台 IM 的本地标注工具：保存问题、输入语言和多模态素材，导入普通/长截图的标准 PNG 输出，由用户判断好坏并确认金标，再将金标与评测命令接入 GitHub CI。详见 [评测设计与边界](evaluation.md)。Eval 独立运行，不代表生产渲染器、多模态解析或云服务已完成。

## 定位

专业开源的聊天场景创作工具，附带技术风格的官网。官网未来提供 Web 入口和 MCP/API 接入说明。核心场景包括产品演示、教学、叙事素材与合成评测数据。

## 用户提出的能力

- Web 以对话交互开始，左右布局呈现输入与预览，允许自然语言反复修改。
- 将不同 IM 平台的界面元素抽象为可配置模板和变量；支持单聊、群聊、人物头像、消息时间、手机时间及状态。
- 覆盖文字、图片、语音、视频、定位、加好友提示、系统提示，以及模拟红包和转账卡片等消息类型。
- 支持保存用户头像偏好，默认普通截图，并可选择长截图。
- 允许上传已获授权的截图或图片，多模态提取为可编辑的结构化内容，再进行修改和渲染。
- Web 与 MCP/API 复用程序化渲染能力；未来支持在 ChatGPT 和 Claude 内调用并展示生成结果。
- 按需接入图像生成、视频生成和搜索能力。

## 开源与托管方向

用户希望项目开源、Web 免费可用，并对托管 MCP/API 采用充值 key 模式。具体免费额度、渲染与 AI 成本的计费边界、key 生命周期、定价及支付供应商均未确定。先保留这些决策，不在初始化阶段接入计费。

## 架构方向（待实现阶段确认）

结构化 conversation contract → 确定性渲染 → 图像输出。Web、API、MCP 作为不同入口；截图解析和 AI 素材生成属于辅助能力。暂未选择 Web 框架、数据库、渲染运行环境、身份供应商或模型供应商。

## 待确认事项

首批平台与消息类型、模拟内容标识方式、上传素材保留期、导出尺寸、AI 供应商与成本限制、身份和授权方式、部署拓扑。
